## LangChain Implementation — qa-bot-ts

This document explains how LangChain is used in this project, the main integration points, and where to look to change behavior.

### Overview

The project uses LangChain (core + community + provider adapters) to implement:
- Document loading and parsing
- Embeddings generation
- MongoDB-backed vector store (LangChain MongoDB adapter)
- Retrieval pipeline (keyword / vector / hybrid)
- Optional LLM re-ranking of retrieval candidates
- Question-answering and conversational RAG chains

Top-level code that wires everything together lives under `src/` (server, lib, pipelines).

### Key packages

- `@langchain/core` — main primitives: prompts, messages, runnables, documents, chat models
- `@langchain/community` — file loaders (PDF, DOCX, etc.)
- `@langchain/mongodb` — MongoDB Atlas Vector Search integration
- Provider adapters: `@langchain/openai`, `@langchain/groq`, `@langchain/mistralai`, `@langchain/anthropic`

See `package.json` for exact versions used.

### Main components (files)

- `src/utils/documentLoader.ts` / `src/lib/loaders.ts`
  - Uses LangChain community loaders (`PDFLoader`, `DocxLoader`) to convert files to plain text `Document`s. Files are normalized and joined into a single string for QA endpoints.

- `src/lib/embeddings/*.ts`
  - Provides a small factory to create Embeddings objects based on configured provider (Mistral, OpenAI, etc.). These are passed into the vector store.

- `src/lib/vectorstore/resumeVectorStore.ts`
  - Wraps LangChain's `MongoDBAtlasVectorSearch`.
  - Responsible for initializing the vector store, adding documents (converting to `Document` objects), running similarity searches, and batch ingestion.

- `src/lib/models/factory.ts`
  - Creates chat models for the configured provider using LangChain provider adapters (ChatOpenAI, ChatGroq, ChatAnthropic, ChatMistralAI, or a testleaf adapter).
  - Central place to switch provider, set temperature, max tokens, and validate API keys.

- `src/lib/chain.ts`
  - Builds QA chains (a prompt -> model -> StringOutputParser pipeline) using LangChain `ChatPromptTemplate` and `Runnable` composition. Chains are cached for reuse.

- `src/lib/conversationalRAGChain.ts`
  - Implements a conversational RAG manager using `RunnableSequence` with a prompt template that includes chat history + formatted search results.
  - Handles follow-ups (filtering previous results), loads memory, and saves exchanges to memory.

- `src/pipelines/retrieval/pipeline.ts` and related files (`keywordSearch.ts`, `vectorSearch.ts`, `hybridSearch.ts`, `llmReranker.ts`)
  - Encapsulates retrieval logic: keyword, vector, or hybrid search.
  - Optionally runs an LLM-based re-ranker (`LLMReranker`) to semantically filter and score retrieved candidates.

- `src/server.ts`
  - HTTP endpoints that expose QA, conversational chat, document uploads, and resume search. It wires `createChatModel()`, `RetrievalPipeline`, `ResumeVectorStore`, and QA/conversational chains together.

### Data flow (ingestion → query)

1. Ingestion: files uploaded via `POST /search/documents` are processed by `loadDocumentToString()` which uses LangChain loaders.
2. The resulting text is converted to `Document` objects and saved to MongoDB via `ResumeVectorStore.addResumes(...)`. Embeddings are generated by the configured Embeddings provider and stored under an `embedding` field.
3. Query: client calls `POST /search/resumes` or `POST /chat`.
   - `RetrievalPipeline.search()` runs a keyword/vector/hybrid retrieval to fetch candidates.
   - If LLM re-ranking is enabled and a chat model is available, `LLMReranker` invokes the model to filter & re-score candidates.
   - For QA and chat, a chain is built (`buildQAChain` or `ConversationalRAGChainManager`) that formats prompts, injects search results and chat history, then runs the chat model to produce a final answer.

### Configuration (env variables)

Key environment variables used by the LangChain integration:
- `MODEL_PROVIDER` — one of `groq`, `openai`, `anthropic`, `mistral`, `testleaf`
- `GROQ_API_KEY`, `OPENAI_API_KEY`, `ANTRHOPIC_API_KEY`, etc. — provider API keys
- `GROQ_MODEL`, `OPENAI_MODEL`, etc. — model names
- `TEMPERATURE` — model temperature
- `MONGODB_URI`, `MONGODB_DBNAME`, `MONGODB_COLLECTION` — vector store connection and collection
- `EMBEDDING_PROVIDER`, `EMBEDDING_MODEL` — which embeddings implementation to use

See `src/lib/models/factory.ts` and `src/server.ts` for exact names and defaults.

### Extensibility

- To add a new provider: add a new case in `createChatModel()` and wire the provider adapter (LangChain usually exposes a ChatX class).
- To change prompt behavior: edit `src/lib/prompts.ts` (system and human prompt templates) or add a new `PromptType` and pass to `buildQAChain`.
- To swap embeddings: update factory in `src/lib/embeddings/index.ts` to return `Embeddings` compatible with LangChain.

### Where to look when debugging

- Document parsing issues: `src/lib/loaders.ts` and `src/utils/documentLoader.ts`.
- Embedding failures: `src/lib/embeddings/*` and vector store initialization in `src/lib/vectorstore/resumeVectorStore.ts`.
- Retrieval ranking surprises: `src/pipelines/retrieval/` (keyword/vector/hybrid engines and `llmReranker.ts`).
- Prompting & chain behavior: `src/lib/chain.ts`, `src/lib/prompts.ts`, and `src/lib/conversationalRAGChain.ts`.

### Security and production notes

- API keys should be set via environment variables and never committed.
- Large file uploads should be handled using direct-to-cloud or chunked uploads for production.
- LLM re-ranking can add latency and cost — tune `llmRerankConfig.retrievalTopK`.
- Consider caching model outputs and limiting per-user requests.
